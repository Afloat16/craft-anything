# Native Windows coordination observations for #2183

This is a temporary validation branch in `Afloat16/craft-anything`, based directly on
`f3715a5539b28ae24ba244c7dc5f6f865257f3cf`. Its workflow and probe are not intended for the upstream PR.
The branch does not change production source or the production lockfile.

The workflow only responds to pushes to `test/r2.9-windows-coordination-20261125`
in that fork. It uses `contents: read`, disables persisted checkout credentials, uses no
secret inputs, and has no release, signing, permission, PR, or publication operation.
The checkout and artifact actions are pinned to the same revisions already used by the
repository's shared CI. Artifacts contain logs, the observed OS/filesystem, and source hashes.
The pinned actions were checked against
[`craft-common-actions` gate at `1754016e67ca9b74dfa4cf4678b2ac3548e9840f`](https://github.com/storytold/craft-common-actions/blob/1754016e67ca9b74dfa4cf4678b2ac3548e9840f/.github/workflows/gate.yml).

## Scope

Both jobs require native x86_64 Windows, NTFS, and Rust 1.100.0. The small probe records
the actual result, `ErrorKind`, and Windows error number of each filesystem operation.
An operation failing is an observation, not a predetermined expected failure. Setup,
empty-directory rename baseline, or exclusive-lock premise failures make the probe fail.

Cases cover an empty directory, open directory handles, an open file without a byte-range
lock, an exclusive file lock, relocation of the still-held lock to a private sibling slot,
a delayed initializer creating another public lock, and renaming a root whose child
directories remain open. Cleanup observations separately retain and drop the file,
inbox-directory, private-directory, and root-directory handles. The delayed initializer's
new lock is preserved; the old lock is never restored over it. No probe case claims to
implement a safe application cleanup protocol.

The other job runs exactly these existing production engine tests, independently recording
both exit codes and verifying that each command actually started one test:

- `workspace::tests::creation_reservation_is_released_after_definite_picked_folder_publication_failure`
- `workspace::tests::deletion_reuses_reserved_cleanup_space_after_removing_the_manifest`

This is focused native evidence, not a full engine, application, or platform test-suite claim.

## Source and fixture provenance

`src/lib.rs` contains the three unchanged child-opening helpers extracted from the published
`crates/platform/src/fs.rs` at the baseline above, under this repository's MIT/Apache-2.0
licensing. `src/main.rs` and the workflow scripts are original Afloat16 validation code,
licensed under MIT OR Apache-2.0 and recorded in this directory's `ATTRIBUTION.md`. Every runtime
directory and empty coordination file is generated by this probe inside an exclusively
created job-owned temporary directory; no personal or third-party fixtures are read.
Root directory handles in the small probe use standard Rust `OpenOptions` with directory
semantics and default delete sharing. The full production tests retain the exact `same-file`
identity-handle implementation, so the small probe does not substitute for those tests.

The standalone crate reuses the already checked helper harness's locked dependency graph:

- `fs_at = 0.2.1`, Apache-2.0, unmodified dependency, Robert Collins;
  <https://docs.rs/crate/fs_at/0.2.1/source/Cargo.toml>.
- `windows = 0.62.2`, MIT OR Apache-2.0, unmodified dependency, Microsoft;
  <https://docs.rs/crate/windows/0.62.2/source/Cargo.toml>.

These packages are already present in the production dependency graph and credited by its
`ATTRIBUTION.md` and `NOTICE`. Their implementation is not copied into the probe. The reused
`Cargo.lock` records all registry checksums. The helper source hash and every probe/script
hash are preserved in each job's `environment-and-source.json` artifact.
