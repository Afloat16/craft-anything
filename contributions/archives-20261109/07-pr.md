# Enforce standalone LZMA budgets before large dictionary growth

## Problem
The standalone .lzma reader used default decoder options. Its capped output sink was reached only after the decoder flushed an internal dictionary, so small output budgets could still require large dictionary growth or processing of a damaged tail first.

## Change
Read the standalone size header before decoding, reject declared output above the budget, and bound the decoder's internal dictionary as well as the output sink. Preserve the decoder's 4 KiB minimum window and accept oversized dictionary properties for small valid streams.

This fixes the public standalone reader; the existing Unity raw-piece helper already has its own bounds and is unchanged.

## Validation
Added public-reader regressions for declared sizes, dictionary properties, exact/zero budgets and an over-budget stream with a damaged tail. Exact-commit remote checks are pending.

Roadmap: R3.12.
