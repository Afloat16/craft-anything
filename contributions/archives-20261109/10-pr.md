# Decode concatenated XZ streams and standard stream padding

Source: [f25796a28ead5c1f0b5233778a5578a8bd944684](https://github.com/Afloat16/craft-anything/commit/f25796a28ead5c1f0b5233778a5578a8bd944684)

Upstream PR: [#1383](https://github.com/storytold/craft-anything/pull/1383)

## Problem
The existing XZ decoder expects EOF immediately after one footer. It rejects valid standalone .xz files containing concatenated streams or the standard four-byte stream padding.

## Change
Find stream boundaries backwards using checksummed footers and indexes, then decode each bounded stream in order through one capped sink. Validate index integer encodings, aggregate declared output and padding alignment. No search for magic bytes inside compressed payloads is needed.

Format reference: [XZ file format sections 2 and 4](https://tukaani.org/xz/xz-file-format.txt).

## Validation
Added reference/generated fixtures for multiple and empty streams, padding, exact/insufficient aggregate budgets, truncated later members, damaged checksums and malformed index fields. This retains the existing backing decoder; it does not add a separate hard bound to that decoder's internal XZ block allocation.
