# Read complete gzip packed members and verify their trailers

## Problem
The packed-file reader stripped a gzip header and inflated only the first DEFLATE stream. It could return damaged contents without checking CRC/ISIZE, accept missing trailers, and silently drop later gzip members.

## Change
Use the shared gzip reader to validate each member and consume the entire stored range. Concatenated members share the caller's output budget; size-limit failures retain the TooLarge error, while damaged or trailing bytes produce an error. Manifest-size checks remain in place.

## Validation
Added trailer corruption/truncation, trailing garbage, concatenation, empty-stream and aggregate-limit regressions. Updated the optional-header fixture to carry a real header checksum and trailer. Exact-commit remote checks are pending.

Roadmap: R3.12.
